01

오래된 현황이 다시 게시되는 문제

API 연동 현황을 상태 파일과 문서로 관리했습니다. PR 변경을 확인한 bot이 상태 파일을 수정하도록 했지만, CI 환경에 GitHub CLI가 없어 갱신이 반복 실패했습니다. 문서 동기화는 바뀌지 않은 파일을 다시 게시하고 있었습니다.

02

OpenAPI와 현재 소스를 분석 기준으로

커밋된 OpenAPI와 소스 전체에서 연동 상태를 다시 계산하도록 바꿨습니다. 담당자·메모·수동 예외는 상태 파일에 남기고, 코드에서 알 수 있는 정보는 매번 산출하도록 역할을 나눴습니다. TypeScript AST로 호출 경로를 해석하고 import 관계로 화면 연결을 확인했습니다.

03

구현과 검증을 같은 상태로 취급하지 않기

테스트 파일의 호출은 제품 구현 근거에서 제외했습니다. 정적으로 해석하지 못한 호출과 계약에 없는 호출도 검사 대상으로 드러냈습니다. 코드 연결, endpoint 테스트, 실제 API QA를 별도로 두고, CI가 성공한 커밋의 분석 결과를 문서와 PR 보고서에 연결했습니다.

04

확인한 범위

당시 PR에는 분석·상태 판정 테스트와 문서 동기화 dry-run 통과가 기록돼 있습니다. 이 사례는 분석·게시 구조 개선을 다룹니다. 코드 연결만으로 실제 서버 동작이나 배포 완료를 보장하지 않습니다.
