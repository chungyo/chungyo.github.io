01

배경: 첫 고객 프로젝트, 요구사항부터 시작

국제 리더스 클럽은 현장의 예약과 운영을 다루는 서비스입니다. 플래드랩스 창업 초기 첫 고객 프로젝트에서 정해진 기획·화면 구성이 없는 상태부터 요구사항 정리, 화면 구성, UI 개발과 API 연동을 맡았습니다.

네이버 예약은 외부 서비스에서 처리하고 현장 방문 고객은 별도로 관리하던 환경이었습니다. 고객이 필요로 한 것은 예약 입력 화면 하나보다, 두 경로의 고객과 처리 상태를 함께 확인하는 흐름이었습니다.

02

문제: 예약 경로와 현장 상태가 나뉘어 있었다

고객이 설명한 기존 업무와 통합한 업무
대상기존 업무 맥락서비스에서 다룰 정보
네이버 예약외부 예약 경로를 따로 확인수집된 예약을 현장 예약과 함께 표시
현장 방문 고객현장 접수를 별도로 관리같은 예약 흐름에서 생성·상태 확인
예약 처리 상태서로 다른 경로의 정보를 확인확정·대기·이용 중·완료 상태 조회
직원 간 확인예약·진행 정보 공유 필요같은 대시보드의 상태를 기준으로 확인

과거에 모든 업무를 수기로 처리했는지는 확실하지 않아 그렇게 쓰지 않았습니다. 확인된 문제는 예약 경로와 상태 확인 흐름이 분리돼 있었고 고객이 통합을 필요로 했다는 점입니다.

03

첫 범위: 한 화면에서 운영할 수 있는 버전

팀의 예약 통합 기능을 대시보드와 예약 화면으로 연결하고, 약 2주 만에 첫 사용 가능한 버전을 구축했습니다. 이 기간은 사용자 회고를 기준으로 한 초기 구축 기간입니다.

이후 구현한 예약 시간·상품 변경, 매출 집계와 현장 상태 UX까지 전부 2주 만에 완성했다는 뜻은 아닙니다. 초기 버전과 운영 중 후속 개선을 나누어 설명하는 이유입니다.

본인과 팀의 역할

예약 수집과 백엔드 동기화는 팀의 구현입니다. 제가 맡은 기여는 요구사항·화면·프론트엔드·API 연결과 현장 피드백 반영입니다.

04

현장 방문: 반복 조작을 목록에서 처리하도록

팀과 현장을 방문해 운영자의 반복 조작 불편을 확인했습니다. 주요 상태를 바꿀 때 상세 화면으로 들어가는 흐름을 줄이기 위해 카드 슬라이드로 변경을 시작하고 확인 단계를 거쳐 처리하는 UX를 설계·구현했습니다.

코드 이력에는 주요 상태 변경을 위해 상세 화면에 진입하지 않도록 오른쪽 스와이프를 추가한 변경이 남아 있습니다. 확인 다이얼로그도 있으므로 ‘스와이프 한 번으로 즉시 완료’라고 표현하지 않습니다.

05

운영 기준 보완: 생성일보다 실제 이용일

매출 달력에서는 예약이 생성된 날짜와 실제 이용한 날짜가 다른 경우를 구분했습니다. 집계 기준을 예약 생성일에서 실제 이용일로 수정했고, 예약 시간·상품을 변경하는 운영 기능도 구현했습니다.

현장 피드백에 따라 반잠수정의 정원·배정 현황을 확인하고 변경하는 UI와 카드 색상 표시도 다뤘습니다. 초기 예약 통합 이후 현장 업무를 보며 화면의 정보와 조작을 보완한 작업입니다.

대표적인 후속 변경
운영 작업구현한 변경범위
주요 예약 상태 변경목록의 카드 슬라이드 + 확인상세 화면 진입 없이 처리
예약 변경시간·상품 변경 API 연결현장 운영 기능
매출 확인실제 이용일 기준 집계예약 생성일과 구분
배정 확인정원·배정 변경 UI와 색상 표시현장 피드백 반영
06

결과: ‘절반 정도 줄었다’는 현장 피드백

현장 직원과 대표에게 예약 관리 업무시간이 절반 정도 줄었다는 피드백을 직접 들었습니다. 포트폴리오의 약 50%는 이 피드백을 기준으로 합니다.

결과 수치의 의미와 출처
결과기준해석 범위
약 2주첫 사용 가능한 버전 구축 / 사용자 회고후속 개발 전체 기간은 제외
2개 예약 경로 통합네이버·현장 접수 / 코드 구조운영 시간 개선율과는 다른 구현 범위
업무시간 약 50% 절감현장 직원·대표 피드백예약 관리 업무에 대한 피드백, 전후 시간 로그 실측 아님

고객의 피드백은 제품이 현장에서 어떤 변화를 만들었는지 설명하는 근거입니다. 동시에 전후 예약 수·업무량을 맞춘 시간 측정 자료가 있는 것처럼 말하지는 않습니다.

07

검증과 남은 범위

2026년 9월의 근거 조사에서는 예약 데이터 모델, 외부 동기화 호출, 타임라인과 스와이프 변경 이력을 확인했습니다. 다만 인증이 필요한 운영 화면에서 실제 고객 데이터나 처리량·동기화 성공률은 조회하지 않았습니다.

또한 현재 저장소에는 다른 팀원과 후속 개발자의 변경도 포함돼 있습니다. 현재 서비스가 가진 모든 기능을 제 단독 구현으로 합치지 않고, 작성 이력과 현장 회고가 연결되는 작업만 설명합니다.

08

돌아보며: 통합 화면 이후에도 현장 조작을 봐야 했다

예약을 한곳에 모으는 것과 현장에서 쓰기 편한 흐름을 만드는 것은 연결되지만 서로 다른 작업이었습니다. 첫 버전을 만든 뒤 현장에서 반복되는 조작을 확인하고 상태 변경과 배정 UI를 보완했습니다.

이 경험을 설명할 때는 ‘통합했다’는 기능보다, 고객이 어디에서 정보를 확인하고 어떤 조작을 반복했으며 그 흐름을 어떻게 바꿨는지를 먼저 보여주려 합니다.
