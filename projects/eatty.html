작성 근거

사용자 회고·공개 저장소·당시 작성 기록

01

배경: 개발 경험을 첫 제품 배포까지 연결

Eatty는 음식 취향 테스트 결과를 확인하고 친구와 궁합을 공유하는 첫 창업 MVP입니다. 기획·디자인은 팀과 논의하고 개발은 단독 담당했습니다.

당시 프론트엔드 경험을 바탕으로 테스트·결과·공유 흐름에 범위를 집중하고 Firebase를 활용해 데이터 기능과 첫 배포를 이어갔습니다.

02

초기 범위: 질문에서 공유까지 이어지는 한 흐름

질문 화면 하나를 만드는 것으로 끝내지 않고 결과를 확인한 뒤 다른 사람에게 전달하는 단계까지 연결했습니다. 저장·조회와 공유 링크가 함께 작동해야 사용자 흐름이 이어지는 구조였습니다.

출시를 위해 어떤 후보 기능을 제외했는지는 구체적인 당시 기록이 부족합니다. 검토하지 않은 기능 목록을 만들어 MVP 우선순위 결정의 근거로 붙이지 않습니다.

03

구현 선택: 화면은 직접, 데이터 기능은 Firebase와 연결

직접 구현과 활용한 기능의 범위
영역구현·연결한 내용역할
질문·결과 UI입맛 질문·유형 결과 표시본인 개발
유형·궁합 데이터Firebase 저장·조회와 화면 연결기존 서비스 활용·연동
공유 흐름공유 링크·복사·친구 궁합 연결본인 개발
첫 배포사용 가능한 MVP 공개사용자 회고와 기존 자료

Firebase를 썼다는 기술명보다, 직접 구현할 사용자 흐름과 저장·조회 기능을 연결해 첫 제품을 배포한 범위가 중심입니다. 자체 서버나 데이터베이스를 모두 직접 만든 경험으로 표현하지 않습니다.

04

공유를 구현하고 기록하기

공유 버튼에서는 링크 복사뿐 아니라 공유 횟수 갱신과 share_link 이벤트 기록도 구현했습니다. 테스트를 마친 사용자가 친구에게 결과를 전달하는 흐름을 MVP에 포함한 것입니다.

공유 이벤트 기록 코드가 있다는 사실과 실제로 어떤 지표가 수집됐는지는 별도입니다. 이벤트 호출을 곧바로 고유 사용자 수나 구매 전환으로 해석하지 않습니다.

05

결과 기록: 출시와 유입 수치의 확인 수준

확보한 기록을 어떻게 읽었는가
기록근거현재 표현 범위
첫 MVP 출시사용자 회고·기존 자료배포 경험으로 설명
7일 만에 출시당시 작성 기록정확한 시작·완료 기준 추가 확인
800명 이상 유입당시 작성 기록집계 기간·고유 사용자 정의 확인 필요
169회 공유당시 작성 기록이벤트·횟수 집계 기준 확인 필요

기록에 남은 숫자는 보존하되, 정의가 확인되기 전에는 대표 성과 수치로 내세우지 않습니다. 현재 확정해서 설명할 수 있는 결과는 개발을 단독 담당해 테스트·결과·공유 흐름을 첫 배포까지 연결한 경험입니다.

06

돌아보며: 첫 실행 이후 무엇을 확인해야 하는가

첫 제품에서는 구현할 화면과 데이터 기능을 연결해 사용 가능한 흐름을 만드는 데 집중했습니다. 포트폴리오로 다시 정리하면서는 당시 유입과 공유 기록이 어떤 기간과 단위를 뜻하는지까지 확인해야 제품 결과를 설명할 수 있다는 점이 남았습니다.

출시 이후 사용자 반응으로 어떤 제품 결정을 바꿨는지는 아직 충분한 근거가 없습니다. 그 판단을 새로 만들어내는 대신, 현재 확인한 구현·배포 범위와 추가로 확인할 운영 기록을 구분했습니다.
