01

왜 공통 UI가 필요했나

플래드랩스는 자체 서비스와 여러 고객사의 프로젝트를 병행합니다. 비슷한 버튼과 입력 필드를 프로젝트마다 새로 만들다 보니, 디자인 값과 사용 방식도 조금씩 달라졌습니다. 디자이너가 정한 상태·간격·아이콘 기준을 개발자가 다시 묻고 해석하는 일도 반복됐습니다.

팀이 만들고 싶었던 것은 화면을 복사해 쓰는 템플릿이 아니라, 새로운 제품에서도 같은 기준으로 시작할 수 있는 공용 UI였습니다. 다만 모든 프로젝트를 한 가지 모습으로 통일할 수는 없었습니다. 공통 요소가 많은 B2B 제품을 중심으로 구축하고, 브랜드와 사용 경험이 다른 B2C 프로젝트는 별도 디자인 기준을 두기로 했습니다.

02

제품 개발과 함께 기준을 쌓기

처음부터 모든 컴포넌트를 완성한 뒤 NUVION 개발을 시작하면 제품 일정이 늦어집니다. 그래서 팀은 제품을 만들면서 반복되는 요소를 추출해 디자인 시스템에 더하는 방식으로 방향을 잡았습니다. 컬러·타이포·아이콘 같은 기반을 먼저 맞추고, Button·Chip 같은 기본 요소와 Toast·Modal 같은 조합형 요소로 넓혀갔습니다.

디자인 시스템은 제품 저장소와 분리했습니다. 여러 고객 프로젝트를 한 저장소에 묶지 않아도, 필요한 제품이 패키지 버전을 선택해 설치할 수 있도록 하기 위해서입니다. 컴포넌트를 각각 배포하기보다는 초기 릴리스와 버전 관리를 단순하게 할 수 있는 단일 @plaidlabs/ui 패키지로 묶었습니다. 이 구조와 배포 방식은 팀에서 함께 논의했습니다.

03

디자인 기준에서 사용 가능한 코드까지

디자이너가 Figma에서 정한 컬러·타이포를 코드에 매번 손으로 옮기면 이름이나 값이 어긋나기 쉽습니다. 팀은 디자인 토큰을 JSON으로 관리하고, 개발자가 변환 스크립트를 실행해 코드에서 사용할 값을 생성하는 흐름을 마련했습니다.

컴포넌트는 토큰을 사용해 구현하고, Storybook에 상태와 조합별 예시를 남겼습니다. 제품 팀이 이름만 보고 추측하는 대신 실제 모양과 동작을 확인할 수 있게 하려는 선택이었습니다.

04

내가 맡은 Chip과 Toast

저는 팀의 공통 기준 위에서 Chip과 Toast를 설계·구현했습니다. 두 컴포넌트 모두 한 화면에만 맞춰 만들면 다른 제품에서 다시 예외를 처리해야 했습니다. 어떤 값을 사용하는 쪽에서 넘기고, 무엇을 컴포넌트가 책임질지 먼저 나눴습니다.

Chip — 디자인 조합을 props로 정리

색상·크기·형태·스타일을 조합할 수 있게 만들고, 아이콘만 있는 경우는 텍스트 유무로 판별해 전용 여백을 적용했습니다. 스타일의 variant 타입을 컴포넌트 props에 연결해 디자인 규칙이 바뀌어도 타입 정의가 따로 어긋나지 않도록 했습니다. Storybook에는 주요 조합을 나란히 볼 수 있게 정리했습니다.

Toast — 호출 방식과 닫히는 동작을 분리

제품 화면에서는 제목·설명·상태·액션을 전달하고, 공통 영역이 알림을 렌더링하도록 구성했습니다. 닫기를 누른 즉시 큐에서 제거하면 퇴장 애니메이션을 보여줄 수 없어, 닫기 상태를 먼저 표시하고 애니메이션 후 제거하도록 했습니다. 긴 문구, 액션 유무, 상태별 표현은 Storybook에서 확인할 수 있게 했습니다.

Toast의 큐와 기본 접근성 구성에는 React Aria를 활용했습니다. 제가 구현한 부분은 이를 팀 디자인 토큰, 공용 호출 API, 진입·퇴장 상태와 연결한 영역입니다.

05

npm 패키지로 배포하며 맞춘 사용 방식

컴포넌트가 저장소 안에서 보이는 것과 다른 제품에 설치해 쓰는 것은 달랐습니다. 초기 배포 과정에서는 JavaScript 컴포넌트가 표시돼도 vanilla-extract가 생성한 CSS가 소비 프로젝트에 로드되지 않는 문제가 있었습니다. 팀은 빌드 결과의 진입점에서 CSS를 함께 불러오고, 패키지의 exports와 sideEffects를 정리해 설치한 쪽에서 별도 내부 경로를 찾지 않도록 했습니다.

단일 패키지 구조와 사용 방식은 팀에서 함께 고민했습니다. 저는 Chip·Toast의 공개 export와 Storybook 예시를 맡았고, 패키지 게시와 빌드 문제 해결은 동료가 진행했습니다. 함께 만든 디자인 시스템은 @plaidlabs/ui로 배포됐습니다.

06

제품 적용과 결과

배포 후 NUVION 콘솔에서는 공용 컬러·타이포와 Button, Dropdown 같은 컴포넌트를 가져다 쓰고 있습니다. 제가 만든 Chip은 알림 화면의 상태 표시에, Toast는 여러 화면의 피드백에 연결돼 있습니다. 같은 컴포넌트가 문서 예시를 넘어 실제 제품 코드에서 사용되는 지점까지 확인했습니다.
