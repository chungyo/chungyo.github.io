01

배경: 여러 화면에서 조합해 쓰는 알림

사내 제품 화면에서 상태별 알림에 설명·액션 버튼·닫기 버튼을 조합하고, 디자인에 맞게 CSS를 조정할 수 있는 Toast가 필요했습니다. 공용 컴포넌트는 한 화면에서 보기 좋은 것뿐 아니라 소비 화면이 어떤 정보를 넘길 수 있는지까지 정해야 했습니다.

React Aria의 Toast 구성 요소와 큐를 바탕으로 사내 디자인 토큰, 호출 API와 진입·종료 상태를 구현했습니다.

02

설계: 소비 화면은 내용과 옵션을 전달

공용 API에 담은 정보
분류화면이 전달하는 값공통 컴포넌트의 책임
내용제목·설명긴 문구와 줄바꿈 표현
상태·크기상태별 호출·크기 옵션디자인 토큰과 스타일 적용
상호작용액션·닫기 여부버튼 조합과 닫기 동작
렌더링toast.success / toast.error 등ToastRegion의 공통 렌더링

상태별 표현을 매번 화면에서 조립하지 않도록 호출과 렌더링을 나눴습니다. 큐 자체는 React Aria가 제공하고, 제가 구현한 부분은 소비 화면에 노출할 옵션과 사내 디자인·동작의 연결입니다.

03

문제: 닫는 순간 제거하면 종료 동작을 표현할 수 없다

닫기 요청과 화면에서 실제로 사라지는 시점은 달라야 합니다. 큐에서 바로 제거하면 종료 애니메이션을 표현할 대상이 없어지므로, 먼저 닫는 상태를 알리고 지정한 시간이 지난 뒤 제거하도록 구성했습니다.

04

핵심 구현: 상태 구독과 중복 닫기 처리

진입·종료 상태는 useSyncExternalStore로 구독하고 스타일에 전달했습니다. 이미 닫는 중인 항목에 추가 닫기 요청이 들어오면 무시하도록 처리했습니다.

시간을 기준으로 제거하는 구조이므로 CSS 재생 시간과 큐 제거 시점을 함께 관리해야 합니다. 움직임 감소 설정에 맞춘 스타일도 포함했지만, 이를 모든 접근성 요구의 검증 완료로 표현하지 않습니다.

05

사용 시나리오: Storybook에서 조합 확인

정리한 사용 시나리오
축확인할 조합목적
상태·크기각 상태와 크기디자인 표현 비교
본문짧은 문구·긴 문구·설명내용 길이에 따른 배치
액션액션 있음·없음사용자가 취할 다음 행동
닫기닫기 있음·없음 및 조합소비 화면의 사용 방식

이 조합을 Storybook에서 같은 환경으로 확인할 수 있게 정리했습니다. Storybook 예시의 존재를 자동 회귀 테스트나 전 소비 화면의 검증 완료와 동일하게 쓰지 않습니다.

07

이 사례에서 남긴 설계 기준

소비 화면이 전달할 정보와 컴포넌트 내부의 수명주기를 분리했습니다. 특히 사용자에게는 한 번의 닫기처럼 보여도 구현에서는 닫기 요청·종료 표현·큐 제거를 별개 단계로 다뤄야 했습니다.
